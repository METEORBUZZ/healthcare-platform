# 💻 Frontend Engineer — Private Hospital Management Software

## 1. Role

The Frontend Engineer converts approved UI/UX designs into a responsive, accessible and production-ready web application.

The application provides separate interfaces for Admin, Doctor, Staff and Patient. Patients have a restricted portal for viewing and downloading only their own medical reports.

## 2. Recommended Technology

- React.js
- TypeScript
- Vite
- Tailwind CSS
- React Router
- REST API integration
- Form validation

## 3. Main Responsibilities

### UI Development

Build:
- Login
- Dashboards
- Navigation/sidebar
- Profiles
- Tables
- Forms
- Cards
- Modals
- Notifications
- Reports
- Search and filters
- Loading and error states

## 4. Role-Based Interfaces

### Admin Dashboard
- Dashboard overview
- Doctor management
- Staff management
- Patient management
- Department management
- Shift management
- Report management
- User activation/deactivation
- Audit logs
- Settings

### Doctor Dashboard
- My patients
- Patient details
- Medical records
- Medical history
- Prescriptions
- Patient reports
- My shift
- Profile

### Staff Dashboard
- Assigned patients
- Assigned tasks
- Task status
- My shift
- Working location
- Notifications
- Profile

### Patient Portal

Keep the patient interface simple:
- My profile
- My reports
- Report details
- Report preview
- Report download

Patients must not see other patients, admin management, staff management, doctor management or internal hospital operations.

## 5. Authentication UI

Implement:
- Login
- Logout
- Session handling
- Invalid-login feedback
- Session-expired state
- Unauthorized page
- First-login password change
- Password validation
- Forgot/reset password UI if supported by backend

```text
Admin creates user

        ↓

        ↓

        ↓

```

## 6. Role-Based Navigation

```text
Login
  ↓
Authentication
  ↓
User Role
  ├── Admin   → Admin Dashboard
  ├── Doctor  → Doctor Dashboard
  ├── Staff   → Staff Dashboard
  └── Patient → Patient Portal
```

Frontend route protection improves the user experience, but backend authorization must always enforce actual access control.

## 8. Patient Report Access

```text
Patient Login
      ↓
My Reports
      ↓
Select Report
      ↓
View Report
      ↓
Download Report
```

The frontend must not assume that a report belongs to a patient based only on UI state. The backend must verify ownership and authorization for every report request.

Forms may include:
- Login
- Doctor
- Staff
- Patient
- Shift
- Department
- Medical record
- Prescription
- Report upload
- Password change

Each form should have:
- Required-field validation
- Correct data types
- Clear error messages
- Submit/loading state
- Success feedback
- Cancel/reset behavior

## 10. Report UI

Support:
- Report list
- Search
- Filters
- Report type
- Report date
- Report details
- Preview where supported
- Download
- Upload for authorized users
- Upload progress
- Upload failure state

## 11. Responsive Design

The application must work on:
- Desktop
- Laptop
- Tablet
- Mobile

Desktop can use a full sidebar and data tables. Mobile should use collapsible navigation, responsive cards, stacked forms, mobile-friendly tables and large touch targets.

Important workflows such as checking a shift, opening a patient and viewing a report must remain usable on mobile.

## 12. UI States

Every important screen should support:
- Loading
- Empty state
- Success
- Validation error
- Server error
- Unauthorized
- Session expired
- No search results

## 13. Accessibility

Use:
- Semantic HTML
- Keyboard navigation
- Visible focus states
- Accessible labels
- Readable typography
- Sufficient contrast
- Accessible error messages
- Touch-friendly controls
- Status communication that does not rely only on color

## 15. Frontend Security Responsibilities

- Do not expose secrets in frontend code.
- Protect authenticated routes.
- Handle unauthorized API responses.
- Clear sessions on logout.
- Avoid displaying unauthorized patient data.
- Validate file types and sizes before upload.
- Avoid putting sensitive data unnecessarily in URLs.

Backend authorization remains the final security boundary.

## 17. Definition of Done

Frontend work is complete when:
- All four role-based interfaces are implemented.
- UI matches approved UI/UX designs.
- Routes are role-aware.
- Backend APIs are integrated.
- Forms have validation.
- Loading, empty, success and error states are implemented.
- Patient report UI is restricted to the intended patient experience.
- Application is responsive.
- Accessibility basics are implemented.
- No secrets are stored in frontend code.
- Production build completes successfully.
- Frontend is ready for deployment.
