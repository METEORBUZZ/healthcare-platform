# UI/UX Design Specification: Private Hospital Management Software

**Document Version:** 1.0  
**Status:** Approved for Implementation  
**Target Roles:** Admin, Doctor, Staff, Patient  

---

## 1. Executive Summary & Purpose

The purpose of this document is to define a secure, role-based, accessible, and responsive UI/UX system for a Private Hospital Management platform. The system operates across four primary personas:
- **Admin:** Complete governance of users, staff, schedules, clinical departments, system settings, and audit logs.
- **Doctor:** Clinical workspace for assigned patients, medical history review, treatment plans, prescriptions, diagnostic orders, and shift tracking.
- **Staff (Nurses, Technicians, Ward Admins):** Operational workspace for managing task queues, shift rosters, ward locations, and patient care workflows.
- **Patient:** Strictly partitioned, privacy-compliant portal permitting access only to the individual's authenticated diagnostic reports and core profile data.

## 5. Critical User Journeys

### Journey 1: Provisioning & First-Time Login (Admin -> Staff)
1. Admin opens `/admin/users` and triggers `[+ Create New User]`.
2. Form captures: Full Name, Role (`Staff`), Department (`Emergency`), Email.
3. System outputs a temporary, high-entropy one-time password (OTP).
4. Staff member accesses the app via `/login`.
5. Authentication middleware identifies `force_password_reset = true`.
6. User is redirected to `/auth/first-login-change`.
7. Once updated with an 8+ character, mixed-case, numeric password, the user is redirected to the `/staff/dashboard`.

### Journey 2: Patient Report Verification & Download
1. Patient logs in at `/login`; server assigns session scope `ROLE_PATIENT` bound to `patient_id`.
2. Patient navigates to `/portal/reports`.
3. Patient clicks `[View]` or `[⬇ Download]`.
4. An inline modal renders a PDF preview showing metadata (Patient Name, Record ID, Date, Prescribing Doctor).
5. Patient clicks `[Download Official PDF]`. The request issues a signed, expiring URL token to stream the encrypted asset.

## 6. System Edge States & Handlers

| State Type | Interface Presentation Pattern | System Action / Recovery Path |
| :--- | :--- | :--- |
| **Loading / Skeleton** | Shimmer skeleton cards match the final UI dimensions (`#E2E8F0` to `#F1F5F9`). | Prevents cumulative layout shifts (CLS); user actions are disabled during fetch. |
| **Empty State** | Centered icon with an informative heading and explanatory paragraph. | Primary CTA button directs the user to the starting action (e.g., `[Assign First Shift]`). |
| **Input Validation** | Red border (`--color-danger-base`), `⚠` icon, and caption text directly under the input. | Highlights the error on blur or submission; moves focus to the first erroneous input. |
| **Unauthorized (403)** | Full-page state with a shield-alert icon: *"Access Restricted: You lack permissions for this ward/view."* | CTA: `[Return to Dashboard]`. Logs access violation to backend audit ledger. |
| **Session Expired (401)** | Centered modal overlay dimming the view: *"Your session has expired due to inactivity."* | Action: `[Re-Authenticate]`. Maintains the target URL parameter for redirect post-login. |

## 7. Multi-Device Responsive Architecture

### Breakpoint Standards
- **Desktop ($\ge 1280\text{px}$):** Persistent 260px sidebar, full data grids with inline sorting, multi-column clinical summaries.
- **Tablet ($768\text{px} - 1279\text{px}$):** Collapsible 72px icon rail with hover tooltips, 2-column cards, horizontally scrollable data tables.
- **Mobile ($\le 767\text{px}$):** Top utility bar with mobile hamburger menu, persistent 4-tab bottom navigation, data tables transformed into vertical action cards (minimum 44px tap targets).

### Mobile Table Transformation Pattern
For screen viewports $< 768\text{px}$, wide tabular data converts to stacked interactive cards:

## 8. Frontend Engineering Handoff Checklist

- [ ] **Semantic HTML:** All pages use `<header>`, `<nav>`, `<main>`, `<aside>`, and `<section>`.
- [ ] **Table Headers:** All `<th>` elements define `scope="col"` or `scope="row"` with `aria-sort` attributes.
- [ ] **Color Independence:** All status pills pair color with an explicit icon and descriptive label.
- [ ] **Focus Management:** Focus rings visible with `2px solid #06B6D4` and `2px offset`.
- [ ] **Live Regions:** Dynamic status changes and upload progress bars declare `role="status"` and `aria-live="polite"`.
- [ ] **Client Routing Guards:** Prohibit direct URL routing to restricted paths without validated session claims.
